# Bat Siege — project brief for Claude Code

Read this file, then `docs/GAME_SPEC.md`, `docs/ART_GUIDE.md`, and `docs/MILESTONES.md` before writing code.

## What we're making

**Bat Siege** is a mobile-first 3D strategy-action game for the **RUN October Jam** (theme: Monster Mash).
You play a bat defending a block castle on a 6x3 grid. You fly out to eat moths (the currency),
build and reinforce your castle at home, and raid the rival bat's castle by dropping rocks and termites.
**While you're away from home, your castle can't grow.** That tension is the whole game.

- Jam rules: built on RUN, started after Oct 8 2026 noon PT, published to public AND entered via
  "Enter the jam" in RUN's Creator Hub before **Nov 2 2026, 12:00 PT**. Original IP only.
- Target prize: the RUN team's **Editor's Picks** ($15k top pick). Judges reward polish and feel,
  not feature count. Also eligible for "Most Sticky" and "Best Use of Theme".

## 3D assets (Blender pipeline)

All models are generated by `blender/build_assets.py`. Nothing is hand-modeled, so we can regenerate
and tweak anytime.

```bash
# from the project root (macOS path shown; on other systems use `blender`)
/Applications/Blender.app/Contents/MacOS/Blender -b -P blender/build_assets.py -- --out assets/models --preview
```

- Output: `assets/models/*.glb` and preview renders in `assets/previews/*.png`.
- **Open the preview PNGs and check them visually** after every change to the script. Compare to
  `reference/concept.jpg`. Fix anything that looks broken (holes, flipped faces, floating parts).
- The script was written without being run. Expect a few Blender API errors on first run; read the
  traceback, fix the script, rerun with `--only <asset_name>` to iterate on one asset quickly.
- Requires Blender 4.2 LTS (free from blender.org). Check `blender --version` first.
- Also works headless with the `bpy` pip module (Blender 5.1.2, Python 3.13), see README.md. The models in
  `assets/models` were built that way.

### How the game uses the models (performance)

`src/render/assets.js` "bakes" each .glb at load: every material color is written into vertex colors and
the meshes are merged, so a block piece is 1 draw call (+1 for glowing parts like torch flames). Blocks are
drawn with InstancedMesh (one draw call per piece type for both castles); damage tint uses instance colors.
Glow sprites, sparkles, and debris are each a single instanced draw call. A typical frame is ~50 draw calls
and ~150k triangles. Wall bricks only bevel their visible face and drop the hidden back face.

### Asset conventions the game code must respect

| Rule | Value |
|---|---|
| Units | 1 unit = 1 meter. Grid cell spacing 1.5, block footprint 1.3, block level height 0.8 |
| Up axis | Y-up in Three.js (exporter converts from Blender Z-up) |
| Front | Models face **+Z** in Three.js |
| Block origin | bottom-center |
| Stacking | A block of level N = N copies of `block_<type>_body` (or `_gate` on the ground level of the two front-middle squares) at y = floor + i*0.8, then `block_<type>_cap_<keep|wall|corner>` at y = floor + N*0.8, picked by position; wall caps face out |
| Castle floor | top of floor is y = 0.24 above `castle_frame` origin; empty `GridOrigin` marks it |
| Grid cells | cell (col c, row r) center = (-3.75 + 1.5c, 0.24, rowZ0 + 1.5r) relative to castle center |
| Torches | empties named `TorchSocket_*` mark flames: add an additive glow sprite + flicker there |
| Pond | child mesh `MoonReflection` turns red during the blood moon |
| Animations | `bat_player`, `bat_rival` are skinned meshes on a 25-bone rig (shoulder/elbow/wrist/thumb/4 fingers per wing, head, ears, legs). No baked clip: `src/render/batRig.js` animates the bones in code (fold-on-upstroke wing beat, banking, ear flop, legs, stun flail). `moth` has a looping wing-flap |
| Damage look | multiply each block's material color toward dark as HP drops (clone materials per block) |

Turrets: `turret_base` (one level) + `turret_head` (rotating cannon; empties `GhostSeat`, `Muzzle`) with the ghost seated in it.

## Performance budget (judges play on phones)

- 60 fps on a mid-range phone. Test on Zyrus's phone every milestone.
- Device pixel ratio capped at 1.75 on touch devices; shadow map 1024 on mobile, 2048 on desktop.
- Under ~150 draw calls and ~200k triangles on screen. If the brick-detailed blocks are too heavy,
  merge static castle geometry, or add a `--lowpoly` path to the Blender script with fewer bricks.
- One directional moonlight with shadows; everything else is emissive or sprite glow, no extra
  real-time lights.
